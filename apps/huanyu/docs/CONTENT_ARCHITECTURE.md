# 寰宇一体化平台 App · 内容架构（Information Architecture）

> 版本：v1.0.0　日期：2026-09-17　配套文档：`docs/ARCHITECTURE.md`（技术架构）
> 本文回答："App 里到底有哪些内容、内容怎么组织、怎么流转、怎么扩充"。
> 一句话概括：**一条内容（新闻 / 视频 / 直播 / 团单 / 商品）既是内容，也是交易入口；用户产生的一切（评论、点赞、下单、支付）又反过来变成新内容沉淀到消息与账单里。**

## 3. 内容域与内容资产清单

### 3.1 资讯内容（新闻）

| 项 | 内容 |
| --- | --- |
| 频道 | 推荐、国内、国际、财经、科技、体育、娱乐、汽车、文化、健康（10 个，`ChannelDef.all`） |
| 内容单元 | `Article`：标题 / 摘要 / 来源 / 发布时间 / 频道 / 配图 / 正文块（段落、图片） |
| 内容来源 | 本机门户服务 `GET /api/v1/feed`、`/api/v1/news/:id`（增量同步预留 `/api/v1/sync`）；失败静默兜底 |
| 组织方式 | 分频道缓存 + 下拉刷新，`ChannelDef.nameOf(id, cn)` 双语频道名 |
| 延伸 | 稿件详情页保留分享 / 评论占位，后续接入"新闻 → 话题 → 视频/直播"的跨形态跳转 |
| 扩展动作 | 新增频道：改 `models.dart` 的 `ChannelDef.all` 即可，Tab 与请求参数自动跟随 |

### 3.2 视频 / 直播内容

| 项 | 内容 |
| --- | --- |
| 载体 | `assets/videos/clip1-3.mp4`（720p，约 3MB），`video_player` 真实解码播放 |
| 内容单元 | `VideoItem`：标题 / 作者 / 话题标签 / 点赞·评论·分享数 / 封面渐变 `ColorSeed` / **asset 路径** / 关联商品 `productIds` / `live` 标志 / `viewers` |
| 现有内容 | 5 条：**2 条直播**（财经早班车、国际局势一周盘点）+ 3 条短视频（地铁新线实拍、AI 科普、深夜食堂） |

| 互动内容 | 评论抽屉（点赞评论、发评论）、直播飘屏留言 |
| 交易挂载 | 视频同款商品条 / 直播间购物袋 → `productIds` → 商详 → 下单（订单 `source=video/live`） |

### 3.8 交易内容配图策略（2026-09-18 统一）

| 位置 | 图片来源 | 规格 | 兜底 |
| --- | --- | --- | --- |
| 商城商品卡 / 商详轮播 | `Product.images[]`（`assets/shop/pX_Y.jpg`） | 1200×1200 | `ColorSeed` 渐变块 |
| 本地生活团单 | `LocalDeal.image`（`assets/life/dX.jpg`） | 1200×900 | 同上 |
| **订单卡片 / 订单详情** | `OrderItem.image`（下单时从上述两者快照） | 同上 | `_ItemThumb` 内 `errorBuilder` 回退渐变块 |

规则：
1. **下单即快照** —— 订单行项保存图片路径，商品后续换图不影响历史订单（与价格快照同一原则）。
2. **缺图永不破图** —— `image` 为空或 asset 加载失败一律回退 `ColorSeed` 渐变块。
3. **素材入库体检** —— 新增/替换素材后按「尺寸 ≥1200×900、灰度标准差 ≥12、非纯色非全黑」自检，历史上 `p9_2`（黑黄警示条纹）、`p9_3`（全黑）、`life/d5`、`d7` 就是漏检混入的失效图，已重抓替换。

## 5. 内容流转链路

```
① 生产：RSS 采集 / 编辑后台（门户）  ──► 稿件池 ──► /api/v1/feed ──► 新闻频道流
② 二创：稿件 → 短视频 / 直播选题 ──► VideoItem（挂载 productIds）
③ 分发：视频 ←→ 商城（同款）←→ 生活（到店券）←→ 小程序
④ 互动：点赞 / 评论 / 直播留言 ──► InteractionMsg（消息中心）──► 回跳原内容
⑤ 转化：视频/直播/商城/生活 ──► 订单（带 source）──► 收银台 ──► 账单
⑥ 沉淀：发货 / 收货 / 评价 / 退款 ──► 订单时间轴 + 客服系统消息 + 互动消息
⑦ 复购：订单 → 再次购买 / 评价 → 商品页 → 新一轮 ⑤
```

关键约定：**任何用户行为都要"落内容"**——下单必须产生账单，评论必须进入互动消息，退款必须进会话与订单时间轴。这是本内容架构与"各自独立的静态假数据"最大的区别。

## 8. 内容扩展操作手册

| 想加什么 | 改哪里 | 需要什么字段 |
| --- | --- | --- |
| 新闻频道 | `core/models.dart` → `ChannelDef.all` | id（对应后端频道）、name、nameEn |
| 一条视频 / 直播 | `core/mock.dart` → `Mock.videos` | id、title(+En)、author、asset（或后续 url）、seed、tags、productIds、`live` |
| 一个商品 | `core/mock.dart` → `Mock.products` | id、title、price、originPrice、specs/specOptions/skus、shop、reviews、sales |
| 一个团单 | `core/mock.dart` → `Mock.deals` | id、category、price、originPrice、rating、distance、store、package、notes |
| 一个会话 | `core/mock.dart` → `Mock.sessions` + `initialMessages()` | id、name(+En)、avatarText、unread + 初始消息 |
| 一个小程序 | `core/mock.dart` → `Mock.miniApps` | id、name、desc、icon、category |
| 一条初始账单 | `core/mock.dart` → `initialBills()` | title、time、amount、type、icon、category |
| 一单初始订单 | `state/app_state.dart` → `_seedOrders()` | 见 `Order` 字段（注意 `logisticsNo` 留空会自动生成 `trackingNo`） |

**配图抓取**：`tools/fetch_assets.js`（零依赖，Node 18+）负责商城 10×3 张与本地生活 8 张真实照片的抓取与替换 —— Bing 图片搜索取原图直链 → 尺寸门槛逐级放宽 → dHash 去重 → Pillow 居中裁切 → 输出渐进式 JPEG（商品 1200×1200、团单 1200×900），失败时保留原图绝不留下破图。常用：`node tools/fetch_assets.js --only=shop | --only=life | --files=p2_2,p10_1`。

**命名规范**：视频 `v#`、商品 `p#`、团单 `d#`、会话 `s#`、小程序 `m#`、订单 `HY<yyyyMMdd>###`。
**注意**：商品 id 一旦被 `Mock.videos` 的 `productIds` 引用，就构成"视频同款"关系；订单的 `fromVideoId` 与视频 id 对齐才能回跳。

## 9. 内容治理与升级路线

| 阶段 | 内容侧目标 |
| --- | --- |
| v1.1 | 内容落盘：购物车 / 订单 / 账单 / 会话本地持久化，重启不丢 |
| v1.2 | 接 CMS：稿件、商品、团单、小程序全部走后端接口，`Mock` 退化为离线兜底 |
| v1.3 | 审核与合规：评论 / 直播留言 / 评价进入审签流，敏感词与风控 |
